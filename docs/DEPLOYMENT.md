# Deployment

## 1. Current setup (interim proxy)

The Vercel GitHub app does not yet have access to `geomarkdesigns/Yasemi-`, so Vercel cannot build from Git.
The production deployment (Vercel project **yiasemi**, team **GMdesigns**, https://yiasemi.vercel.app) therefore
contains only two files:

| File | Purpose |
|---|---|
| `vercel.json` | Rewrites every URL to the built files in this public repo via jsDelivr, pinned to exact commits. Security headers. |
| `middleware.js` | Runs on Vercel before anything is served: **access gate** (pre-launch) and **real 404 pages**. |

```
browser → Vercel edge → middleware.js ── gate (401 + code form) / unknown URL (404 page)
                                    └─ known URL → rewrite → cdn.jsdelivr.net/gh/geomarkdesigns/Yasemi-@<commit>/public/…
```

- **Pages** come from the current commit and are served with `Cache-Control: private, no-store` (rewrite caching is disabled, so no stale page can be served).
- **Images, fonts, favicon** come from the commit where they last changed, so their URLs and caches survive content-only releases. JPEG fallbacks are capped at 1200px (1600px JPEGs timed out through jsDelivr; every current browser uses WebP).
- **Security headers** (from `deploy/security-headers.json`, generated by `build.py`): CSP with a hashed inline theme script, HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, `Permissions-Policy`. While gated, `X-Robots-Tag: noindex, nofollow` as well.
- **Access gate:** the code is the `ACCESS_CODE` environment variable (type *sensitive*) on the Vercel project. It is never in this repository. Sessions last for the browser session only, end when the visitor leaves the site, and expire after 12 hours at most. If `ACCESS_CODE` is missing while the gate is on, the site answers 503 (fails closed).

### Known limitations of the proxy
- Depends on jsDelivr. Its first fetch of a new file can fail, so **always warm before deploying** (below).
- Every change needs a manual deployment (no automatic deploys on push).
- The repository must stay **public** (jsDelivr cannot read private repos), so built pages are publicly readable on GitHub even while the site is gated.

## 2. Releasing a change (proxy)

```bash
python3 build.py && npm test                 # build + unit + E2E (local)
git commit -am "…" && git push origin main
python3 deploy/make_proxy.py --warm          # pre-launch (gate ON); --live for public launch
# then create a production deployment of the Vercel project "yiasemi" with the body in
# deploy/deployment.json (Vercel API: POST /v13/deployments, or the Vercel MCP create_deployment tool)
BASE_URL=https://yiasemi.vercel.app ACCESS_CODE=<code> npx playwright test --project=desktop-chromium --project=mobile-chromium
```
`deploy/deployment.json` is git-ignored. It contains no secrets, only the config and middleware.

## 3. Going live (public launch)

1. The owner approves everything in `docs/CLIENT-VERIFICATION.md` (at minimum: operating status, address, menu and prices).
2. `python3 deploy/make_proxy.py --live --warm` writes a config with the **gate off** and **no noindex header**. Deploy it.
3. Optionally delete the `ACCESS_CODE` environment variable in Vercel.
4. Submit `https://yiasemi.vercel.app/sitemap.xml` (or the custom domain's) in Google Search Console.

## 4. Moving to a direct Git-connected deployment (recommended)

This removes the jsDelivr dependency, gives automatic deploys on push, edge caching, Vercel's native 404 handling,
and allows the repository to become private.

1. On GitHub: https://github.com/apps/vercel → **Configure** → *Repository access* → add **Yasemi-**.
2. In Vercel, project **yiasemi** → Settings → Git → **Connect** `geomarkdesigns/Yasemi-`, production branch `main`.
   Framework preset: *Other*. Build command: *(empty)*. Output directory: `public`. (These also come from the repo's `vercel.json`.)
3. Keep the gate during pre-launch: `python3 deploy/make_proxy.py --git-middleware` writes `middleware.js` at the repo root
   (gate on, native 404). Commit and push it. For launch, run it with `--live` (or delete `middleware.js`) and push.
4. The repo's `vercel.json` (generated by `build.py`) already sets `cleanUrls`, `trailingSlash: false`, long-lived caching for
   `/images`, `/fonts` and versioned `/css`, `/js`, and all security headers. While gated, add the `X-Robots-Tag: noindex` header
   to it (or rely on the gate's 401 for every URL).
5. Push to `main`. Verify: every route returns 200 with the code, unknown routes return the jasmine 404 page with status 404,
   and the headers are present (`curl -sI https://yiasemi.vercel.app/menu`).
6. Optional: make the GitHub repository private (no longer needed for jsDelivr).
7. Optional: custom domain. Add it in Vercel → Domains, then change `BASE` in `build.py`, rebuild and push (canonical URLs, sitemap and structured data use it).
